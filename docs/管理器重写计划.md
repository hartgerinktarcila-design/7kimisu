# 7kimisu 管理器重写计划（manager-next）

## 前提决策（已定）

- **保留包名 `com.sevenk.core`**：内核签名信任集（`KSU_EXPECTED_SIZE/HASH` = 0x034d / 490c6662…）、断代闸门 GEN=2、用户数据 `/data/adb/sevenk` 全部不动，老用户直接覆盖升级。
- 新版本线：**v3.0.0** 起（versionCode = 3000000，高于 v2.29 的 2290000）。
- 旧 `manager/` 目录保留作参照，新工程在 `manager-next/`，达到功能对齐后再替换。

## 重写目标

1. **砍双皮肤**：旧版每个屏幕 Material + Miuix 两份实现，维护成本翻倍。新版只用 **Miuix**（0.9.4，含 miuix-nav）。
2. **砍死代码**：应用锁（app_lock，内核侧已是空壳）不移植；ioctll 22-24 保留内核兼容但 UI 不再有入口。
3. **架构从简**：单 Activity + miuix-nav + ViewModel(StateFlow) + 手写 repository；无 DI 框架。
4. **特效/个性化默认收敛**：调色板保留，雪花/巨魔雨等特效做成可选开关，壁纸宿主后置。

## 必须原样保留的契约（碰错=内核不认主）

- `app/src/main/assets/ksu_manager_gen2` 空标记文件（断代闸门，缺了显示"未安装"）
- JNI：`libsevenk.so`（复用 `manager/app/src/main/cpp/` 整套源码，CMake 相对路径引用）；
  `Natives$Profile` 的类全限定名与字段签名（jni.cc 硬编码 `GetFieldID`）
- supercall ioctl：结构体布局照 `uapi/supercall.h`；stealth 先 25/26 失败退 27/28 的回退逻辑
- 密令入口：`StealthReceiver`（Telephony.SECRET_CODE，默认 70707，发送方校验 v2.29 规则，5 次错锁 30 秒，密令不进日志）+ `StealthCodeStore`（磁盘+prefs 双写并集比对）
- 隐身：`/data/adb/sevenk/stealth` 路径与内核 `stealth.c` 逐字符一致；三态语义（读不到按"可能开着"）
- `libadbroot.so`（adb root 补丁）照旧打包
- ksud 以 `lib/<abi>/libksud.so` 打进 APK（复用旧 jniLibs 产物）
